# X-Fleet — установка

Здесь лежат готовые выпуски X-Fleet (вкладка **Releases**): программа для Linux (amd64, arm64),
установщик `install.sh` и контрольные суммы `SHA256SUMS`. Ниже — как поставить.

X-Fleet — панель для управления VPN на Xray сразу на многих серверах. Ставится одной командой,
без Docker и отдельной базы данных.

## Что нужно

- Сервер (VPS) с **Ubuntu 22.04+** или **Debian 12+**, процессор amd64 или arm64.
- Вход на сервер под **root** по SSH.
- Желательно свой домен (например, `panel.example.com`) с A-записью на IP сервера.
  Без домена тоже можно: панель возьмёт бесплатное имя вида `1-2-3-4.sslip.io`.
- Открытые порты у хостера (в его панели управления, если там есть свой файрвол):

| Порт | Зачем |
|---|---|
| 80 | Let's Encrypt проверяет домен, чтобы выдать сертификат |
| случайный (покажет установщик) | вход в панель |
| 8444 | к панели подключаются ноды |
| 2096 | ссылки подписок для клиентов |
| 443 и 8443 | сам VPN (если этот сервер тоже раздаёт VPN) |

Если на сервере включён `ufw`, установщик сам откроет в нём нужные порты.

## 1. Установка панели

Зайдите на сервер под root и выполните:

```bash
bash <(curl -fsSL https://github.com/richdodcom-pixel/x-fleet-releases/releases/latest/download/install.sh)
```

Откроется мастер установки. Он задаёт вопросы по шагам. Если не уверены, нажимайте Enter: это выбирает вариант по умолчанию.

1. **Язык:** русский или English.
2. **Проверка системы и пакеты.** Установщик предложит обновить систему (`apt upgrade`).
   На сервере, где уже что-то работает, можно отказаться.
3. **Адрес и HTTPS.** Впишите свой домен или выберите вариант без домена (sslip.io).
   Сертификат Let's Encrypt панель получит сама.
4. **Настройки панели.** Порт, секретный адрес и логин выбираются случайно, пароль создаётся сам.
5. **VPN на этом сервере.** Можно сразу сделать этот же сервер первой нодой:
   - VLESS Reality XHTTP на порту 443 (основное подключение);
   - TCP + Vision на порту 8443 (запасное).

   Ещё здесь выбирается сайт для маскировки и заводится первый пользователь.
6. **Запуск и проверка.** Службы запускаются и после перезагрузки сервера поднимаются сами.

В конце на экране будут **адрес панели, логин и пароль**, а также QR-код подписки первого пользователя.
Данные для входа сохраняются в файл `/root/x-fleet-admin.txt`. Посмотреть их снова можно так:

```bash
cat /root/x-fleet-admin.txt
```

### Установка без вопросов

Добавьте `--yes`, и всё выберется по умолчанию. Остальные параметры можно задать сразу:

```bash
bash <(curl -fsSL https://github.com/richdodcom-pixel/x-fleet-releases/releases/latest/download/install.sh) --yes --domain panel.example.com
```

| Параметр | Что делает |
|---|---|
| `--lang ru\|en` | язык установщика и меню |
| `--domain panel.example.com` | свой домен панели и подписок |
| `--https le\|ip\|self\|none` | HTTPS: свой домен / без домена (sslip.io) / самоподписанный / без HTTPS (только через SSH-туннель) |
| `--cert файл --key файл` | свой готовый сертификат вместо Let's Encrypt |
| `--email you@example.com` | почта для писем Let's Encrypt |
| `--port 31234` | порт панели (по умолчанию — случайный) |
| `--login имя` | логин администратора (по умолчанию — случайный) |
| `--connections rec\|xhttp\|vision\|none` | VPN на этом сервере: оба подключения / только XHTTP / только Vision / не ставить |
| `--mask neighbor\|self\|<сайт>` | маскировка Reality: сайт-сосед по подсети / свой сайт на сервере / указанный сайт |
| `--user имя` | первый пользователь (по умолчанию `user`) |
| `--name имя` | имя сервера в приложениях клиентов, латиницей |
| `--upgrade` / `--no-upgrade` | обновлять систему или нет |
| `--bbr` / `--no-bbr` | включить ускорение TCP (BBR) или нет; по умолчанию включается |
| `--version v0.7.1` | поставить конкретную версию |

Полная справка по параметрам:

```bash
bash <(curl -fsSL https://github.com/richdodcom-pixel/x-fleet-releases/releases/latest/download/install.sh) --help
```

## 2. Первый вход

1. Откройте в браузере адрес, который показал установщик, например
   `https://panel.example.com:31234/AbCdEf123/`.
   Адрес секретный: без правильного пути панель не откроется, сканеры её не найдут.
2. Войдите с логином и паролем из `/root/x-fleet-admin.txt`.
3. Рекомендуем сразу:
   - «Настройки» → «Безопасность»: сменить пароль и включить двухфакторный вход;
   - «Настройки» → «Уведомления»: подключить Telegram, чтобы узнавать о сбоях;
   - «Настройки» → «Система»: включить резервные копии по расписанию.

## 3. Добавление нод (других серверов)

1. В панели откройте «Ноды» → «Добавить ноду». Укажите имя и адрес сервера (IP или домен).
2. Панель покажет команду установки. Скопируйте её.
3. Зайдите на новый сервер под root и выполните эту команду.

Команда одноразовая и действует 15 минут. Если не успели, нажмите «Новый токен установки».
Нода сама скачает программу и Xray, подключится к панели, и подключения на ней создадутся автоматически.

> **Если на сервере уже работает другой VPN** (например, 3x-ui) и порты 443/8443 заняты,
> установщик ноды остановится и покажет, какая программа держит порт. Так старый VPN не сломается.

## 4. Пользователи и подписки

«Пользователи» → «Новый пользователь». У каждого пользователя есть ссылка подписки: её добавляют в приложение
(v2rayNG, Happ, v2RayTun, Streisand, Hiddify, INCY, NOX, Clash/Mihomo, sing-box). Страница подписки
показывает QR-код и кнопки для приложений.

## Управление с сервера: команда `x-fleet`

Наберите на сервере `x-fleet`, и откроется меню. Быстрые команды:

| Команда | Что делает |
|---|---|
| `x-fleet url` | показать адрес панели и логин |
| `x-fleet password` | новый пароль администратора |
| `x-fleet 2fa off` | выключить двухфакторный вход (если потеряли телефон) |
| `x-fleet status` | состояние служб |
| `x-fleet restart` | перезапустить службы |
| `x-fleet log` | журнал |
| `x-fleet port 31234` | сменить порт панели |
| `x-fleet path` | новый секретный путь панели |
| `x-fleet https` | сертификат панели |
| `x-fleet update` | обновить X-Fleet |
| `x-fleet backup` | резервная копия сейчас |
| `x-fleet check` | проверка сервера |
| `x-fleet link имя` | ссылка подписки пользователя с QR-кодом |
| `x-fleet node-cmd` | команда установки новой ноды |

## Обновление

- **Панель:** «Настройки» → «Система» → «Обновление панели». Или на сервере: `x-fleet update`.
  Прежняя версия сохраняется для отката.
- **Ноды:** «Настройки» → «Ядра»: обновить Xray и агентов на всех нодах разом.
  Или по одной, на странице ноды.

## Смена адреса или домена панели

«Настройки» → «Сеть и сертификаты». Здесь меняются порт, секретный путь и сертификат
(свой домен, sslip.io или самоподписанный).

- Сертификат на новый домен панель получает **до** переключения. Если Let's Encrypt откажет, ничего не изменится,
  а на экране будет причина.
- После смены откройте панель по новому адресу и войдите **в течение 10 минут**. Иначе прежние настройки вернутся сами,
  и доступ не потеряется.

## Если что-то не работает

- **Не выдаётся сертификат:**
  - проверьте, что A-запись домена указывает на IP сервера, а в Cloudflare стоит «серое облако»;
  - проверьте, что порт 80 открыт у хостера;
  - Let's Encrypt выдаёт не больше 5 сертификатов на одно имя за неделю. При частых переустановках подождите
    или временно выберите вариант без домена (sslip.io).
- **Забыли адрес или пароль:** зайдите на сервер и выполните `x-fleet url` или `x-fleet password`.
- **Общая проверка:** `x-fleet check`.

## Удаление

```bash
x-fleet uninstall
```

Команда останавливает службы, удаляет программу, настройки и данные. Резервные копии остаются в `/var/lib/x-fleet/backups`.

## Для тех, кто обновляется со старых версий (nodepanel)

До v0.5.0 программа называлась `nodepanel`. При обновлении кнопкой всё переезжает на новые имена само:

| Было | Стало |
|---|---|
| `/usr/local/bin/nodepanel` | `/usr/local/bin/x-fleet` (старое имя остаётся ссылкой) |
| службы `nodepanel-panel`, `nodepanel-node` | `x-fleet-panel`, `x-fleet-node` |
| `/etc/nodepanel`, `/var/lib/nodepanel`, `/var/lib/nodepanel-node` | `/etc/x-fleet`, `/var/lib/x-fleet`, `/var/lib/x-fleet-node` |
| `/root/nodepanel-admin.txt` | `/root/x-fleet-admin.txt` |

Если новая служба не поднялась, всё возвращается как было. Повторить вручную можно командой `x-fleet migrate`,
журнал переезда: `journalctl -u x-fleet-migrate`.
