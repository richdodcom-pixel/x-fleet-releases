# X-Fleet — التثبيت

يحتوي هذا المستودع على إصدارات X-Fleet الجاهزة (تبويب **Releases**): برنامج لنظام Linux (amd64 وarm64)،
وبرنامج التثبيت `install.sh`، ومجاميع التحقق `SHA256SUMS`. فيما يلي طريقة التثبيت.

X-Fleet لوحة لإدارة VPN مبني على Xray على عدة خوادم في وقت واحد. يُثبَّت بأمر واحد،
دون Docker ودون قاعدة بيانات منفصلة.

> برنامج التثبيت وواجهة اللوحة متوفران بـ**الإنجليزية** و**الروسية**. أسماء القوائم والأزرار أدناه مكتوبة بالإنجليزية كما تظهر في اللوحة.

## المتطلبات

- خادم (VPS) يعمل بنظام **Ubuntu 22.04+** أو **Debian 12+**، بمعالج amd64 أو arm64.
- دخول بصلاحيات **root** عبر SSH.
- يُفضَّل نطاق خاص بك (مثل `panel.example.com`) مع سجل A يشير إلى عنوان IP الخادم.
  يمكن الاستغناء عن النطاق: ستستخدم اللوحة اسمًا مجانيًا مثل `1-2-3-4.sslip.io`.
- منافذ مفتوحة لدى مزوّد الاستضافة (في لوحة تحكمه إن كان لديه جدار حماية خاص):

| المنفذ | الغرض |
|---|---|
| 80 | يتحقق Let's Encrypt من النطاق لإصدار الشهادة |
| عشوائي (يعرضه برنامج التثبيت) | الدخول إلى اللوحة |
| 8444 | اتصال العُقد باللوحة |
| 2096 | روابط الاشتراك للعملاء |
| 443 و8443 | الـVPN نفسه (إذا كان هذا الخادم يقدّم VPN أيضًا) |

إذا كان `ufw` مفعّلًا على الخادم، فسيفتح برنامج التثبيت المنافذ اللازمة فيه تلقائيًا.

## 1. تثبيت اللوحة

ادخل إلى الخادم بصلاحيات root ونفّذ:

</div>

```bash
bash <(curl -fsSL https://github.com/richdodcom-pixel/x-fleet-releases/releases/latest/download/install.sh)
```

<div dir="rtl">

سيفتح معالج التثبيت ويطرح الأسئلة خطوة بخطوة. إن لم تكن متأكدًا فاضغط Enter: سيُختار الخيار الافتراضي.

1. **اللغة:** الروسية أو الإنجليزية.
2. **فحص النظام والحزم.** يقترح برنامج التثبيت تحديث النظام (`apt upgrade`).
   على خادم يعمل عليه شيء بالفعل يمكنك الرفض.
3. **العنوان وHTTPS.** أدخل نطاقك أو اختر خيار بدون نطاق (sslip.io).
   ستحصل اللوحة على شهادة Let's Encrypt بنفسها.
4. **إعدادات اللوحة.** يُختار المنفذ والمسار السري واسم الدخول عشوائيًا، وتُنشأ كلمة المرور تلقائيًا.
5. **VPN على هذا الخادم.** يمكنك جعل هذا الخادم العقدة الأولى مباشرة:
   - VLESS Reality XHTTP على المنفذ 443 (الاتصال الرئيسي)؛
   - TCP + Vision على المنفذ 8443 (احتياطي).

   هنا أيضًا يُختار موقع التمويه ويُنشأ المستخدم الأول.
6. **التشغيل والفحص.** تبدأ الخدمات وتعمل تلقائيًا بعد إعادة تشغيل الخادم.

في النهاية تُعرض على الشاشة **عنوان اللوحة واسم الدخول وكلمة المرور**، ورمز QR لاشتراك المستخدم الأول.
تُحفظ بيانات الدخول في الملف `/root/x-fleet-admin.txt`. لعرضها مرة أخرى:

</div>

```bash
cat /root/x-fleet-admin.txt
```

<div dir="rtl">

### التثبيت بدون أسئلة

أضف `--yes` وسيُختار كل شيء افتراضيًا. ويمكن تمرير بقية المعاملات مباشرة:

</div>

```bash
bash <(curl -fsSL https://github.com/richdodcom-pixel/x-fleet-releases/releases/latest/download/install.sh) --yes --domain panel.example.com
```

<div dir="rtl">

| المعامل | ماذا يفعل |
|---|---|
| `--lang ru\|en` | لغة برنامج التثبيت والقائمة |
| `--domain panel.example.com` | نطاقك الخاص للوحة والاشتراكات |
| `--https le\|ip\|self\|none` | HTTPS: نطاق خاص / بدون نطاق (sslip.io) / شهادة ذاتية التوقيع / بدون HTTPS (عبر نفق SSH فقط) |
| `--cert ملف --key ملف` | شهادتك الخاصة بدل Let's Encrypt |
| `--email you@example.com` | بريد لإشعارات Let's Encrypt |
| `--port 31234` | منفذ اللوحة (عشوائي افتراضيًا) |
| `--login اسم` | اسم دخول المدير (عشوائي افتراضيًا) |
| `--connections rec\|xhttp\|vision\|none` | VPN على هذا الخادم: الاتصالان / XHTTP فقط / Vision فقط / بدون |
| `--mask neighbor\|self\|<موقع>` | تمويه Reality: موقع مجاور في الشبكة الفرعية / موقعك على الخادم / الموقع المحدد |
| `--user اسم` | المستخدم الأول (افتراضيًا `user`) |
| `--name اسم` | اسم الخادم في تطبيقات العملاء، بأحرف لاتينية |
| `--upgrade` / `--no-upgrade` | تحديث النظام أو عدمه |
| `--bbr` / `--no-bbr` | تفعيل تسريع TCP (BBR) أو لا؛ مفعّل افتراضيًا |
| `--version v0.7.1` | تثبيت إصدار محدد |

الشرح الكامل للمعاملات:

</div>

```bash
bash <(curl -fsSL https://github.com/richdodcom-pixel/x-fleet-releases/releases/latest/download/install.sh) --help
```

## 2. الدخول الأول

1. افتح في المتصفح العنوان الذي عرضه برنامج التثبيت، مثل
   `https://panel.example.com:31234/AbCdEf123/`.
   العنوان سري: بدون المسار الصحيح لن تُفتح اللوحة، ولن تعثر عليها أدوات الفحص.
2. ادخل باسم الدخول وكلمة المرور من `/root/x-fleet-admin.txt`.
3. ننصح فورًا بما يلي:
   - **Settings ← Security**: غيّر كلمة المرور وفعّل الدخول بخطوتين؛
   - **Settings ← Notifications**: اربط Telegram لتعرف بالأعطال؛
   - **Settings ← System**: فعّل النسخ الاحتياطي المجدول.

## 3. إضافة العُقد (خوادم VPN أخرى)

**العقدة** (node) خادم يتصل عبره العملاء بالـVPN. تدير اللوحة العقد عن بُعد.
تحتاج كل عقدة جديدة إلى **أمر تثبيت**. تصدره اللوحة نفسها، وهو غير موجود على GitHub:
يحتوي الأمر على عنوان لوحتك ومفتاح لمرة واحدة.

### الخطوة 1. احصل على الأمر من اللوحة

1. افتح اللوحة في المتصفح وادخل.
2. من القائمة اليسرى اختر **Nodes**.
3. اضغط الزر الأزرق **Add node** (أعلى اليمين).
4. املأ النموذج:

   | الحقل | ماذا تكتب |
   |---|---|
   | **Name** | أي اسم واضح بأحرف لاتينية، مثل `amsterdam-1` |
   | **Address (IP or domain)** | عنوان IP للخادم الجديد، مثل `203.0.113.10`. سيراه العملاء في الاشتراك |
   | **Node domain (for camouflage)** | يمكن تركه فارغًا. إن كان لديك نطاق بسجل A يشير إلى IP هذا الخادم فأدخله، مثل `nl1.example.com` |
   | **Country** و**City** | يمكن تركهما فارغين: ستحددهما اللوحة من IP. سيرى العملاء مثلًا `🇳🇱 Netherlands, Amsterdam` |
   | **Add inbounds from templates right away** | اتركه محددًا: ستُنشأ الاتصالات على العقدة تلقائيًا |

5. اضغط **Create**.
6. ستُفتح نافذة **Install node** وفيها أمر طويل يبدأ بـ `curl -fsSL https://…/node.sh | bash -s -- …`.
   اضغط أيقونة **النسخ** على يمين الأمر.

يبدو الأمر تقريبًا هكذا (سيكون العنوان والرمز والبصمة مختلفة لديك):

</div>

```text
curl -fsSL https://panel.example.com:2096/install/Ab12Cd/node.sh | bash -s -- --panel panel.example.com:8444 --token 7f3a… --pin 9c1e…
```

<div dir="rtl">

> **مهم:** الأمر صالح لمرة واحدة ولمدة **15 دقيقة** (وقت الانتهاء مكتوب في النافذة).
> لم تلحق أو أغلقت النافذة؟ افتح **Nodes** ← اضغط على العقدة ← **New install token**،
> وسيظهر أمر جديد.

**طريقة أخرى: من خادم اللوحة.** ادخل عبر SSH إلى الخادم المثبّتة عليه اللوحة ونفّذ:

</div>

```bash
x-fleet node-cmd
```

<div dir="rtl">

سيسأل البرنامج عن اسم العقدة وعنوان IP والنطاق (Enter: بدون نطاق) ويطبع أمرًا جاهزًا صالحًا لمدة 30 دقيقة.

### الخطوة 2. نفّذ الأمر على الخادم الجديد

1. ادخل عبر SSH إلى **الخادم الجديد** (العقدة المستقبلية، لا خادم اللوحة) بصلاحيات root:

</div>

```bash
ssh root@203.0.113.10
```

<div dir="rtl">

2. الصق الأمر المنسوخ (في الطرفية: زر الفأرة الأيمن أو Ctrl+Shift+V / Cmd+V) واضغط Enter.
3. انتظر 1–2 دقيقة. ستقوم العقدة تلقائيًا بما يلي:
   - تنزيل البرنامج من لوحتك والتحقق من مجموع التحقق؛
   - الاتصال باللوحة عبر قناة آمنة؛
   - تنزيل Xray وتشغيله.

### الخطوة 3. تحقّق

عُد إلى اللوحة ← **Nodes**. خلال ثوانٍ ستظهر حالة خضراء للعقدة الجديدة.
الاتصالات من القوالب أُنشئت بالفعل. ستظهر العقدة في اشتراكات مستخدمي المجموعة التي تنتمي إليها
(قسم **Squads**). لا حاجة لتغيير رابط الاشتراك: سيجلب التطبيق الخادم الجديد عند تحديث الاشتراك.

### إذا لم ينجح الأمر

- **"install token expired" (انتهت صلاحية رمز التثبيت):** احصل على أمر جديد: صفحة العقدة ← **New install token**.
- **العقدة لا تتصل باللوحة:** يجب أن يكون المنفذ **8444** مفتوحًا على خادم اللوحة
  (و**2096**، فمنه يُنزَّل البرنامج). تحقّق من جدار حماية المزوّد.
- **يعمل على الخادم الجديد VPN آخر بالفعل** (مثل 3x-ui) والمنفذان 443/8443 مشغولان: سيتوقف برنامج التثبيت
  ويعرض البرنامج الذي يشغل المنفذ. بهذا لن يتعطل الـVPN القديم. حرّر المنافذ أو عيّن لهذه العقدة
  منافذ أخرى في اللوحة.
- **العقدة هي خادم اللوحة نفسه:** لا حاجة لتثبيت شيء، فمعالج تثبيت اللوحة يعرض ذلك مباشرة (خطوة "VPN على هذا الخادم").

## 4. المستخدمون والاشتراكات

**Users** ← **New user**. لكل مستخدم رابط اشتراك يُضاف إلى التطبيق.
تعرض صفحة الاشتراك رمز QR وأزرارًا للتطبيقات.

### تطبيقات العملاء

| التطبيق | كيف تضيف الاشتراك |
|---|---|
| **NOX** (موصى به، Android 7+) | [تنزيل NOX.apk](https://github.com/richdodcom-pixel/nox-updates/releases/latest/download/NOX.apk). زر **NOX** في صفحة الاشتراك يفتح التطبيق ويضيف الاشتراك |
| Happ وHiddify وINCY وv2RayTun وStreisand وv2rayNG وClash Verge / FlClash | زر التطبيق في صفحة الاشتراك (أو الصق رابط الاشتراك في التطبيق) |
| sing-box وعملاء Clash / Mihomo الآخرون | الصق رابط الاشتراك، وستقدّم اللوحة التنسيق المناسب تلقائيًا |

## الإدارة من الخادم: الأمر `x-fleet`

اكتب `x-fleet` على الخادم لتفتح القائمة. أوامر سريعة:

| الأمر | ماذا يفعل |
|---|---|
| `x-fleet url` | عرض عنوان اللوحة واسم الدخول |
| `x-fleet password` | كلمة مرور جديدة للمدير |
| `x-fleet 2fa off` | إيقاف الدخول بخطوتين (إذا فقدت الهاتف) |
| `x-fleet status` | حالة الخدمات |
| `x-fleet restart` | إعادة تشغيل الخدمات |
| `x-fleet log` | السجل |
| `x-fleet port 31234` | تغيير منفذ اللوحة |
| `x-fleet path` | مسار سري جديد للوحة |
| `x-fleet https` | شهادة اللوحة |
| `x-fleet update` | تحديث X-Fleet |
| `x-fleet backup` | نسخة احتياطية الآن |
| `x-fleet check` | فحص الخادم |
| `x-fleet link اسم` | رابط اشتراك المستخدم مع رمز QR |
| `x-fleet node-cmd` | أمر تثبيت عقدة جديدة |

## التحديث

- **اللوحة:** **Settings ← System ← Panel update**. أو على الخادم: `x-fleet update`.
  يُحفظ الإصدار السابق للرجوع إليه.
- **العُقد:** **Settings ← Cores**: تحديث Xray والوكلاء على جميع العقد دفعة واحدة.
  أو واحدة تلو الأخرى من صفحة العقدة. **Settings ← System ← Update all servers** يحدّث جميع العقد بنقرة واحدة.

## تغيير عنوان اللوحة أو نطاقها

**Settings ← Network & certificates**. هنا يُغيَّر المنفذ والمسار السري والشهادة
(نطاق خاص أو sslip.io أو شهادة ذاتية التوقيع).

- تحصل اللوحة على شهادة النطاق الجديد **قبل** التبديل. إذا رفض Let's Encrypt فلن يتغير شيء،
  وسيظهر السبب على الشاشة.
- بعد التغيير افتح اللوحة على العنوان الجديد وادخل **خلال 10 دقائق**. وإلا ستعود الإعدادات السابقة تلقائيًا،
  ولن تفقد الوصول.

## إذا لم يعمل شيء

- **لا تُصدَر الشهادة:**
  - تحقّق من أن سجل A للنطاق يشير إلى IP الخادم، وأن السحابة في Cloudflare رمادية (DNS فقط)؛
  - تحقّق من أن المنفذ 80 مفتوح لدى المزوّد؛
  - يصدر Let's Encrypt خمس شهادات كحد أقصى للاسم الواحد أسبوعيًا. إن كنت تعيد التثبيت كثيرًا فانتظر،
    أو اختر مؤقتًا خيار بدون نطاق (sslip.io).
- **نسيت العنوان أو كلمة المرور:** ادخل إلى الخادم ونفّذ `x-fleet url` أو `x-fleet password`.
- **فحص عام:** `x-fleet check`.

## الإزالة

</div>

```bash
x-fleet uninstall
```

<div dir="rtl">

يوقف الأمر الخدمات ويحذف البرنامج والإعدادات والبيانات. تبقى النسخ الاحتياطية في `/var/lib/x-fleet/backups`.

## لمن يحدّث من الإصدارات القديمة (nodepanel)

قبل الإصدار v0.5.0 كان اسم البرنامج `nodepanel`. عند التحديث بالزر ينتقل كل شيء إلى الأسماء الجديدة تلقائيًا:

| سابقًا | الآن |
|---|---|
| `/usr/local/bin/nodepanel` | `/usr/local/bin/x-fleet` (يبقى الاسم القديم رابطًا) |
| الخدمتان `nodepanel-panel` و`nodepanel-node` | `x-fleet-panel` و`x-fleet-node` |
| `/etc/nodepanel` و`/var/lib/nodepanel` و`/var/lib/nodepanel-node` | `/etc/x-fleet` و`/var/lib/x-fleet` و`/var/lib/x-fleet-node` |
| `/root/nodepanel-admin.txt` | `/root/x-fleet-admin.txt` |

إذا لم تعمل الخدمة الجديدة، يعود كل شيء كما كان. للتكرار يدويًا: `x-fleet migrate`؛
سجل النقل: `journalctl -u x-fleet-migrate`.
